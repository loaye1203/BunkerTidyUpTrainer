# Bunker Tidy Up Trainer 1.0.3 验证报告

本版只修改安装、恢复与发行配置，不调整游戏玩法、技能数值或游戏存档协议。测试通过 `tests/Trainer.Installation.Tests` 在工作区 `.artifacts/install-recovery-tests/` 下建立独立文件夹夹具；假游戏文件仅用于安装路径校验，没有启动游戏，没有访问真实玩家存档或部署正式游戏插件。

## 自动安装恢复

本地运行的 16 组测试通过：全新安装、仅剩原样 winhttp.dll、手动复制整套文件并缺失插件、共享加载器及其他插件保留、安装记录删除/JSON 损坏/缺字段恢复、游戏路径末尾分隔符一致性，以及对未知代理、其他入口、无法确认的配置值、不同核心、MelonLoader、目录占用和修改过的插件拒绝覆盖。

另外使用实际公开的 1.0.0、1.0.1、1.0.2 便携 ZIP 作为旧插件夹具。下载包的 SHA-256 与 GitHub Release 资产摘要核对一致；三个旧版在无安装记录时均识别并升级。CI 必跑 13 组基础测试，历史 ZIP 夹具在本地缓存存在时补充运行。

测试确认：已有开关配置和侧档文件保留，缺失插件补齐；共享 Doorstop 正确入口的禁用状态可以备份后启用，其他配置内容保留，再次安装检查不会重置配置。模拟原版恢复保存回执后，正常移除删除本工具插件，恢复共享配置，保留其他插件和原有加载器，不重新恢复旧版本工具插件。此回执属于文件管理夹具，不表示本轮重新测试了游戏保存。

不兼容组件在写入前被拒绝，游戏目录文件哈希保持原样，没有创建完成安装记录。没有验证任意第三方模组的运行行为，也没有对不同 BepInEx 版本进行泛化兼容测试。

## 构建与发布

使用固定 .NET 10 SDK、BepInEx 5.4.23.5 和 Unity 6000.0.59f2 引用；控制器仍为 Windows x64 自包含程序，玩家无需另装 .NET。安装程序包含同一便携包，发行资产摘要写入 SHA256SUMS.txt 与 release-metadata.json。游戏内行为的既有验证范围见 1.0.2 历史报告，本版没有重新运行游戏内测试。

本地发行构建成功，0 个错误；包含 NuGet 漏洞索引离线的 NU1900 警告及游戏插件既有未使用字段警告。验证未把这些警告描述为已消除。
